# Параметры: зерновая кривая и ГО

Полный справочник пользовательских настроек расчёта. Сначала зерновая кривая, затем ГО. Входные цены, заявки, позиции, архив и календарь описаны в [INPUT_DATA.md](INPUT_DATA.md), а не являются параметрами методики. Настройки генератора здесь не рассматриваются.

Общий файл: [project_parameters/default_calculation_parameters.json](project_parameters/default_calculation_parameters.json). Если текущие значения подходят, ничего дополнительно заполнять не нужно. Для своих настроек передай полную изменённую копию файла через `--parameters путь/к/файлу.json`. Таблицы ниже отражают текущие defaults, не рекомендации по их калибровке на рынке.

## 1. Параметры зерновой кривой

### 1.1. Настраиваемые пороги

В разделе `forward_curve` для каждого из 39 узлов задаются четыре поля. Даже при одинаковых значениях соседние узлы настраиваются независимо.

| Поле | Человеческое значение | Единицы и ограничения |
|---|---|---|
| `min_trade_volume` | Минимум суммарного дневного объёма сделок, чтобы использовать цену по сделкам | Тонны, больше нуля |
| `min_order_volume` | Требуемая глубина каждой стороны одного среза стакана | Тонны, больше нуля. Используется цена предельной тонны указанного объёма, не средняя цена покупки/продажи этого объёма |
| `threshold_trade_volume` | Дневной объём полного веса сделок при смешивании с ценой заявок | Тонны, больше нуля. Вес равен минимуму из отношения объёма к этому порогу и единицы |
| `spread_max` | Верхняя граница относительного спреда допустимого среза | Неотрицательная доля: `0.008` означает 0,8%. Спред считается относительно полусуммы цен глубины покупки и продажи |

Текущие значения:

| Узлы | `min_trade_volume`, т | `min_order_volume`, т на сторону | `threshold_trade_volume`, т | `spread_max` |
|---|---:|---:|---:|---:|
| 1D, 1W, 2W, 1M–3M | 800 | 100 | 1600 | 0.008 = 0,8% |
| 4M–6M | 200 | 100 | 800 | 0.012 = 1,2% |
| 7M–12M | 80 | 80 | 400 | 0.016 = 1,6% |
| 13M–24M | 80 | 80 | 400 | 0.020 = 2% |
| 25M–36M | 50 | 100 | 250 | 0.030 = 3% |

Файл должен содержать все 39 узлов и все четыре поля у каждого. Локальные изменения можно передать в `parameter_overrides` входа зерновой кривой: объект по узлам с любыми из этих четырёх полей. Они применяются поверх выбранного общего файла. Сохранённый результат содержит эффективные параметры запуска.

### 1.2. Правила, закреплённые в коде

Это не поля общего JSON. Для их изменения требуется отдельное изменение реализации.

| Правило | Текущая реализация |
|---|---|
| Стандартные сроки | 39 узлов: 1D, 1W, 2W, 1M...36M |
| Даты сроков | Календарные дни/месяцы; отсутствующий день месяца заменяется последним днём месяца |
| Время наблюдения | Московское, окно 10:00–18:00 |
| Срезы | 160 состояний: 10:03...18:00 с шагом 3 минуты |
| Событие в момент среза | Применяется до построения среза |
| Минимум валидных срезов | 20; последовательность подряд не требуется |
| Усечение крайних цен | При N > 20 исключается floor(N/10) цен с каждого края; при N = 20 усечения нет |
| Рыночные наблюдения | Безадресные сделки и безадресные лимитные заявки |
| Перенос цены | Без ограничения числа дней, по тому же обозначению срока |
| EMMI | Перенос исходного наблюдения на один точный или два соседних узла; это не интерполяция готовой кривой |
| Интерполяция готовой кривой | Log-linear по фактическим календарным датам |
| Пропуски и выход за диапазон | Не соединяются через отсутствующую соседнюю цену; экстраполяции нет |
| Дополнительная временная устойчивость стакана | Не используется |
| Пересечение стакана после EMMI | Исключается контрактом поставщика входных данных |

Пороги времени, усечения и число узлов нельзя поменять через `parameter_overrides`. Финансовая арифметика публичного расчёта: Decimal, 28 значащих цифр, округление ROUND_HALF_EVEN. Округление на графике и в Excel не задаёт точность расчёта.

## 2. Параметры ГО портфеля

### 2.1. Основные настройки

Все перечисленные поля находятся в разделе `margin` общего файла.

| Поле | Сейчас | Что определяет |
|---|---|---|
| `horizon_days` | `5` | Горизонт риска в торговых днях MOEX; положительное целое |
| `scenarios` | `10000` | Число генерируемых FHS-сценариев; положительное целое |
| `confidence` | `"0.99"` | Доверительный уровень, строго между 0 и 1 |
| `metric` | `"var"` | Мера риска: `var` или `es` |
| `fhs_window` | `1000` | Максимальное число последних дневных изменений для FHS-калибровки; целое, не меньше min_observations |
| `min_observations` | `200` | Минимум дневных изменений для калибровки; целое не меньше 10, нужен соответствующий архив |
| `seed` | `42` | Неотрицательное целое для воспроизводимости сценариев риска. Это не seed генератора входных данных |
| `volatility_mode` | `"forecast"` | Прогноз GARCH; альтернативно `"recent_max"` |
| `recent_window` | `20` | Положительное окно поиска максимальной недавней волатильности в режиме recent_max; в forecast не используется |
| `volatility_floor` | `"0"` | Дополнительная нижняя граница волатильности. Ноль отключает этот нижний порог |
| `min_volatility_ratio` | `null` | Нижняя граница относительно предыдущей волатильности; при включении число от 0 до 1 |
| `previous_volatility` | `null` | Предыдущая волатильность, необходимая при включённом min_volatility_ratio |
| `fhs_target` | `null` | Дополнительный целевой масштаб FHS; null отключает масштабирование |
| `hypothetical_scenarios` | `[]` | Список заданных гипотетических стрессов; пустой список отключает компонент |
| `event_scenarios` | `[]` | Список заданных событийных стрессов; пустой список отключает компонент |
| `concentration` | Объект из раздела 2.3 | Пороги, ставки и корзины концентрационной надбавки |

`null` означает отсутствие настройки, не число ноль. `volatility_floor`, `previous_volatility`, `fhs_target` можно задать скаляром либо 78 значениями: сначала 39 ценовых факторов, затем 39 процентных, в порядке 1D, 1W, 2W, 1M...36M. Значения нижнего порога и предыдущей волатильности неотрицательные; активные цели FHS положительные. Это масштабы факторов модели, не цены в рублях и не готовые суммы ГО.

Окно 1000 относится к числу изменений, а не числу сценариев: для полного окна нужны 1001 снимок, при текущем минимуме достаточно 201. Исторический блок использует весь переданный архив. При 201 снимке и горизонте 5 дней исторических сценариев 196.

### 2.2. Поля каждого заданного стресса

Одинаковый формат для `hypothetical_scenarios` и `event_scenarios`:

| Поле | Что задать | Единицы |
|---|---|---|
| `name` | Непустое название | Строка |
| `forward_return` | Изменение зерновой цены; одно число на всю кривую или 39 значений | Относительная доля: `-0.15` означает -15%; цена после шока должна остаться положительной |
| `zero_shift` | Изменение непрерывной нулевой ставки; одно число или 39 значений | Абсолютная доля: `0.02` означает +2 процентных пункта |

Числа выше поясняют единицы, а не предлагают величины рабочих стрессов. Стрессы автоматически не калибруются.

### 2.3. Концентрационная надбавка

| Поле внутри `margin.concentration` | Сейчас | Что определить |
|---|---|---|
| `limit1` | `null` | Первый порог объёма, т |
| `limit2` | `null` | Второй порог объёма, т; должен быть не меньше первого |
| `addon1_per_tonne` | `"0"` | Ставка надбавки между порогами, руб./т |
| `addon2_per_tonne` | `"0"` | Ставка надбавки выше второго порога, руб./т |
| `buckets` | `[]` | Корзины сроков |

Каждая корзина содержит обязательный `last_tenor`, например `3M` или `36M`, и необязательные собственные `limit1`, `limit2`. Без собственных порогов используются общие. Границы корзин возрастают и должны покрывать сроки позиций; для первой корзины учитываются сроки до её границы, для следующих после предыдущей границы и до своей включительно.

Пороги и ставки неотрицательные. При обеих нулевых ставках компонент выключен; для включения нужны явно заданные корзины, пороги и ненулевые ставки. Объём корзины считается как модуль суммы `side × quantity`, то есть встречные позиции взаимно уменьшаются. Автоматического выбора порогов и ставок нет.

### 2.4. Фиксированные правила модели

| Правило | Реализация |
|---|---|
| Спецификация | ARMA(0,0), GARCH(1,1), стандартизованное распределение Стьюдента |
| Коэффициенты модели | Оцениваются по истории, вручную не вводятся. Ошибка калибровки не подменяется условным ГО |
| Исторические факторы | Сравниваются одинаковые обозначения узлов по дням |
| Дата сценарной оценки | Фиксированная сегодняшняя дата; горизонт задаёт шоки, но не сдвигает дату оценки |
| Ограничение сделок | Фиксация строго после конца горизонта риска; оплата не раньше фиксации; даты в пределах доступных кривых |
| Итог | max(FHS, historical, hypothetical) + event + concentration |
| Денежная оценка | Общая функция оценки сделки, Decimal; статистика и хвостовые меры используют float64 |

Численные настройки оптимизатора и начальной дисперсии являются внутренними деталями реализации, не пользовательскими полями общего JSON. Изменение порядка модели, распределения или способа сценарной оценки требует изменения кода, а не подстановки нового значения параметра.

### 2.5. Процентная кривая и оценка сделки

Для ГО нужны текущие кривые и параметры сделки из [INPUT_DATA.md](INPUT_DATA.md#23-каждая-позиция-в-trades). Отдельного файла коэффициентов NPV нет: сторона, объём, договорная цена и даты относятся к позиции.

| Правило / настройка | Сейчас | Где определяется |
|---|---|---|
| Источник сегодняшней процентной кривой | MOEX G-curve на точную дату расчёта | Общий запуск |
| Коэффициенты B1, B2, B3, T1, G1...G9 | Получаются от MOEX | Рыночные данные, вручную выбирать не нужно |
| Дневная база | ACT/365F | Код дисконтирования |
| Дисконтирование | Непрерывное | Код дисконтирования |
| Короткие сроки G-curve | Ставка берётся на сроке не меньше 0,25 года; время дисконтирования фактическое | Код адаптера |
| Процентная интерполяция в сценарном ГО | Линейная по непрерывным нулевым ставкам между 39 узлами | NodeCurves |
| Процентная кривая отдельного NPV общего запуска | Аналитическая G-curve непосредственно | Адаптер MOEX |
| `timeout` | 20 секунд | Аргумент Python API загрузчика, не общий JSON |
| `use_system_proxy` | false | Аргумент Python API загрузчика, не общий JSON |

## Технические настройки общего запуска

| Аргумент | По умолчанию / назначение |
|---|---|
| `--date` | Явная дата расчёта; иначе run_settings.json, иначе дата Москвы |
| `--input-dir` | Папка `input/` |
| `--defaults-dir` | Папка резервных блоков `default_input/` |
| `--output-dir` | Папка `output/`; внутри создаётся отдельная папка на каждый запуск |
| `--parameters` | Путь к своей полной копии общего файла параметров; без аргумента используется стандартный файл |
| `--serve` | Оставить локальный сервер для пересчёта позиций |
| `--port` | `0`: выбрать свободный порт; сервер слушает 127.0.0.1 |

`schema_version = 1` и `parameter_sources` в общем JSON служат для версии формата и описания происхождения настроек. Они не являются финансовыми параметрами. Эта документация описывает действующую реализацию, а не дополнительные требования биржи.
