# Процентная кривая и дисконт-факторы

Модуль загружает параметры рублёвой G-кривой MOEX и выдаёт дисконт-факторы на заданные даты платежей. NPV, ГО и расчёт зерновой кривой в него не входят. Сторонние зависимости не нужны: используется стандартная библиотека Python 3.12+.

## Как попробовать без интернета

Команды выполняются из папки wheat-curve-calculator:

```powershell
.venv/Scripts/python.exe run_discount_factor_calculation.py --valuation-date 2026-10-26 --payment-dates 2026-10-26 2026-10-27 2026-11-25 2027-10-26 --snapshot examples/moex_g_curve_snapshot_2026-10-26.json --output output/discount_factors.json
```

В examples лежит реальный снимок параметров и опубликованных доходностей, полученный из MOEX ISS за 26.10.2026, 18:54:59 по Москве. Это фиксированный пример, не автоматическое обещание актуальности ставок при следующем запуске.

На выходе output/discount_factors.json. Значения D сохранены десятичными строками; это безразмерные коэффициенты, не процентные ставки.

## Как загрузить другой день

```powershell
.venv/Scripts/python.exe run_discount_factor_calculation.py --valuation-date 2026-10-26 --payment-dates 2026-10-27 2027-10-26 --download --save-snapshot output/moex_g_curve_2026-10-26.json --output output/discount_factors.json
```

Режим --download явно выполняет GET через HTTPS. --snapshot, напротив, только читает локальный файл и никогда не обращается в сеть. Эти режимы взаимоисключающие; один нужно указать. --save-snapshot является необязательным сохранением снимка, --output задаёт файл дисконт-факторов. По умолчанию результат сохраняется в output/discount_factors.json относительно папки программы. Существующий выходной файл заменяется только после успешного расчёта.

Запрос к источнику:

```text
https://iss.moex.com/iss/engines/stock/zcyc.json?date=2026-10-26&iss.meta=off&iss.only=params,yearyields
```

Авторизация и брокерские ключи не используются. HTTPS проверяет сертификат; проверка не отключается. Таймаут функции загрузки по умолчанию 20 секунд. Скрытых повторных запросов и автоматического перехода к другой дате нет.

По умолчанию запрос прямой, без автоматического использования прокси ОС или переменных окружения. Это настройка только данного запроса, системные настройки не меняются. Если доступ к MOEX требует прокси, передать --use-system-proxy в CLI или use_system_proxy=True функции загрузки. Тогда используются прокси, найденные стандартной библиотекой Python. На этом компьютере автоматический системный прокси приводил к TLS-таймауту, поэтому режим подключения сделан явным.

Дата снимка обязана точно совпадать с датой оценки. При пустом ответе за выходной или отсутствующую дату возвращается ошибка. Предыдущий рабочий день не подставляется. Если передать локальный снимок другого дня, он тоже будет отклонён.

Внутри дня используется снимок, возвращаемый данным endpoint на момент запроса, а не специально выбранный снимок на 18:00. Время ответа сохраняется. Во время торгов параметры могут изменяться. Если необходимо повторить тот же расчёт, использовать сохранённый снимок. Режим «снимок на конкретное время» не реализован.

## Python-интерфейс

```python
from datetime import date
from interest_rate_curve import (
    calculate_discount_factors,
    download_moex_g_curve,
    save_moex_g_curve_snapshot,
)

d = date(2026, 10, 26)
curve = download_moex_g_curve(d)
save_moex_g_curve_snapshot(curve, "output/moex_g_curve_2026-10-26.json")

factors = calculate_discount_factors(
    curve,
    [date(2026, 10, 27), date(2027, 10, 26)],
)
# dict[datetime.date, Decimal]: дата платежа -> D(d,T)
```

Загрузка из сохранённого снимка:

```python
from datetime import date
from interest_rate_curve import load_moex_g_curve_snapshot

curve = load_moex_g_curve_snapshot(
    "examples/moex_g_curve_snapshot_2026-10-26.json",
    valuation_date=date(2026, 10, 26),
)
factor = curve.discount_factor(date(2027, 10, 26))
```

Даты передаются как datetime.date, не строки и не datetime.datetime. Строковые даты преобразуются на границе приложения через date.fromisoformat. Совпадающие даты в списке дают один элемент результата; порядок первых появлений сохраняется. Пустой список даёт пустой словарь.

Входом процентного модуля не является JSON заявок/сделок. Он отдельно получает дату оценки и даты платежей, а данные ставок получает из MOEX или локального снимка.

## Как заменить источник

Расчёт NPV должен зависеть только от интерфейса DiscountCurve:

```python
class DiscountCurve(Protocol):
    valuation_date: date

    def discount_factor(self, payment_date: date) -> Decimal: ...
```

Другой адаптер реализует valuation_date и discount_factor, после чего передаётся в ту же calculate_discount_factors. Ему не нужно импортировать MOEX, наследоваться от MoexGCurve или возвращать процентные ставки. Его собственные day-count, модель и источник остаются внутри адаптера. Универсальная функция не навязывает другой кривой ACT/365F или правило короткого конца.

Общий контракт: D является положительным конечным Decimal; D(d,d) = 1, платежи раньше даты оценки запрещены. D > 1 допускается, поскольку такое возможно при отрицательных ставках.

## Что именно отдаёт MOEX

params содержит B1, B2, B3, T1 и G1…G9, а также tradedate и tradetime. Названия параметров сопоставляются по columns, не по заранее заданным позициям.

yearyields содержит period в годах и value: эффективную годовую бескупонную доходность в процентах. Это не непрерывная ставка и не дисконт-фактор. securities с котировками отдельных ОФЗ этому модулю не нужен и не запрашивается.

Для расчёта используются параметры модели, а не интерполяция округлённых value. Таблица yearyields сохраняется для проверки снимка. Проверяется согласованность её даты и времени с params и наличие первого срока 0.25 года. Если структура источника изменится, возвращается ошибка, а не молча выбирается другая конвенция.

Локальный снимок сохраняет блоки params и yearyields в табличной форме ISS. Числа сохраняются строками без потери точности. Дополнительный блок snapshot_metadata содержит источник, URL, московский часовой пояс и версию формата. Загрузчик принимает также исходный JSON ISS с числовыми значениями; JSON-дроби читаются напрямую в Decimal.

## Формулы MOEX и правила проекта

Пусть x является сроком в годах. Соответствие обозначений: beta0 = B1, beta1 = B2, beta2 = B3, theta = T1, g_i = G_i. Непрерывная ставка в базисных пунктах:

```text
G(x) = beta0
     + (beta1 + beta2) × (1 − exp(−x/theta)) / (x/theta)
     − beta2 × exp(−x/theta)
     + Σ_(i=1..9) g_i × exp(−((x − a_i)/b_i)²)

a_1 = 0
b_1 = 0.6
a_(i+1) = a_i + b_i
b_(i+1) = 1.6 × b_i

z(x) = G(x) / 10000
y(x) = 100 × (exp(z(x)) − 1)
```

z является непрерывной ставкой в долях, y эффективной годовой ставкой в процентах. Обозначение theta отделено от срока платежа, чтобы не путать параметр модели T1 с временем до платежа.

Согласованные правила проекта именно для адаптера MOEX:

```text
d = дата оценки, совпадающая с датой снимка
T = дата платежа
tau = фактическое число календарных дней (T − d) / 365
x = max(tau, 0.25)

D(d,T) = exp(−z(x) × tau)
       = (1 + y(x)/100)^(−tau)
```

Это ACT/365F: учитываются выходные и 29 февраля, знаменатель всегда 365. Это выбранная конвенция проекта от нашей даты оценки, а не утверждение о совпадении со всеми конвенциями облигационного рынка MOEX.

При tau < 0.25 фиксируется первая ставка модели z(0.25), а не первый дисконт-фактор. Оставшийся срок tau не заменяется на 0.25. При T = d получаем D = 1. После короткого конца используется непосредственно модель, без дополнительной интерполяции. Сроки более 30 лет отклоняются как выходящие за документированный модельный диапазон; наши зерновые сроки до 36M находятся внутри него.

Все расчёты выполняются в Decimal с точностью 28 значащих цифр и ROUND_HALF_EVEN, независимо от внешнего decimal-контекста. Нет округления до процентного тика и нет преобразования в float.

Пример для фиксированного снимка 26.10.2026: на срок 1 год эффективная ставка модели примерно 14.0534306794%, непрерывная ставка примерно 13.1496842775%, D приблизительно 0.8767820433311845. Нельзя подставлять 0.140534 в экспоненту как непрерывную ставку.

## Ошибки и ограничения

CurveUnavailableError означает отсутствие снимка на точную дату. CurveDataError означает некорректные данные, несовместимые таблицы, неверные параметры или даты. CurveDownloadError означает ошибку HTTPS/сети. Ошибка не превращается в нулевую ставку, D = 1 или снимок другого дня.

CLI возвращает 0 при успехе и 2 при ошибке. Ошибки входа и загрузки не заменяют старый выходной файл, но он может остаться от прежнего успешного запуска. Сохранение снимка и результата не является единой файловой транзакцией: при ошибке записи одного файла второй уже может быть сохранён. Проверять код завершения и выбирать отдельные выходные пути для разных запусков.

Модуль не решает вопрос экономической применимости ОФЗ для конкретного CSA, кредитного риска и стоимости фондирования. Он реализует выбранный источник дисконтирования. Финансовые корректировки в NPV не добавляются автоматически.
