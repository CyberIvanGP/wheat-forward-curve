# Входные данные

Положи пользовательские JSON в эту папку. Эти файлы исключены из Git.

| Имя | Содержимое |
|---|---|
| `run_settings.json` | `{"calculation_date": "2026-10-27"}`. Если файла или даты нет, используется дата запуска по Москве. |
| `wheat_curve_input.json` | `calculation_date`, `previous_date`, `previous_curve`, `events`, `data_kind`; опционально `parameter_overrides`, `source_description`. |
| `portfolio_margin_input.json` | `calculation_date`, `data_kind`, `history_source`, `history`, `trades`. |
| `moex_trading_calendar.json` | Календарь MOEX SPFI: `market`, `coverage_start`, `coverage_end`, `source_url`, `trading_dates`. |

`data_kind`: `REAL` или `SYNTHETIC_TEST`. Для ГО происхождение зерновых данных обязательно. Числа цен и объёмов передавай десятичными строками. Даты: YYYY-MM-DD.

Отсутствующие массивы `previous_curve`, `events`, `history`, `trades` подставляются целиком из одноимённого комплектного файла в `default_input/`. Контекст блока, включая дату и источник архива, берётся из того же файла, что сам блок. `previous_date` относится к `previous_curve`. `parameter_overrides` берётся из пользовательского зернового файла, если он есть, иначе из комплектного. Пустой массив и null не означают отсутствие блока и не заменяются. Некорректный пользовательский файл не заменяется комплектным.

Даты выбранных блоков должны совпадать с датой расчёта. Архив может заканчиваться предыдущим торговым днём: сегодняшний снимок добавляется расчётом. Торговые дни между архивом и сегодняшней датой не достраиваются.

G-curve сюда класть не нужно: единый запуск всегда получает её по HTTPS на дату расчёта. Описание всех полей событий и финансовой математики находится в основном README и `guarantee_collateral/README.md`.

Контракт источника: стакан не пересечён как на исходных сроках, так и после переноса заявок EMMI на узлы. Это гарантия поставщика входных данных; отдельная политика исправления пересечений после EMMI в методику не добавлена.
