# Единый запуск

Это новый порядок работы. Старые `run.py`, `run_discount_factor_calculation.py` и `run_portfolio_margin_calculation.py` оставлены как низкоуровневые команды с прежними аргументами. Их формат папок не изменён. Новые папки по времени создаёт `run_project.py`.

## Windows

Нужен Python 3.12+. В папке проекта один раз создай окружение и установи зависимости, предварительно проверив, что уже установлено:

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip list
.venv/Scripts/python.exe -m pip install -r requirements.txt -r requirements-margin.txt
```

Обычный запуск на текущую московскую дату:

```powershell
.venv/Scripts/python.exe run_project.py --serve
```

Открой напечатанную ссылку `http://127.0.0.1:ПОРТ/`. Сервер работает до Ctrl+C. `run_project.bat` делает тот же запуск двойным кликом. Браузер автоматически не открывается.

Явная дата или комплектный пример:

```powershell
.venv/Scripts/python.exe run_project.py --date 2026-10-27 --serve
.venv/Scripts/python.exe run_project.py --example --serve
```

Комплектный набор пока неполный: смотри `default_input/README.md`. Код не создаёт недостающий архив. Обычный запуск не сдвигает старые примерные данные на сегодня: несовместимость дат вызывает ошибку соответствующего модуля.

Без `--serve` программа рассчитывает и завершает работу, оставляя статический отчёт. В браузере без сервера пересчёты недоступны. Сервер текущего запуска держит подготовленную модель в памяти; возобновление интерактивной сессии из старой папки пока не реализовано.

## Вход и порядок работы

Фиксированные имена файлов описаны в `input/README.md`. Приоритет: пользовательский блок, затем комплектный блок. Неправильный блок не подменяется, пустой массив не заполняется примером. Для повторения разрешено указать `--input-dir`, `--defaults-dir`, `--parameters`, `--output-dir`.

Дата выбирается в порядке: `--date`, `input/run_settings.json`, дата запуска UTC+03:00. В режиме `--example` используются только комплектные файлы и их фиксированная дата. Параметры методики берутся из `project_parameters/default_calculation_parameters.json` либо явно указанного файла.

Зерновая кривая строится по предыдущей кривой и событиям. Независимо от её успеха загружается G-curve по HTTPS на точную дату расчёта. Нет сети или нужного снимка: процентный модуль сообщает ошибку, без скрытого использования вчерашней кривой. NPV и ГО требуют успешно построенную сегодняшнюю зерновую кривую; готовая кривая из архива не заменяет этот шаг.

История ГО проверяется до изменения. В её рабочую копию добавляется сегодняшний снимок; существующий сегодняшний снимок заменяется рассчитанным. Обе операции отмечаются в журнале. Пропуск торгового дня и будущие даты запрещены. Исходник не меняется.

В рабочем архиве непрерывные ставки восстанавливаются из D по ACT/365F. Текущая и сценарная оценка ГО сохраняет прежнюю линейную интерполяцию нулевых ставок. Отдельный NPV использует аналитическую G-curve непосредственно через интерфейс дисконтирования. Это существующие разные способы получения D между узлами, не изменение формул в данном этапе.

Смешение синтетических зерновых данных с реальным архивом помечает эффективный архив как SYNTHETIC_TEST. В обычном запуске расчёт такого ГО требует `--allow-synthetic-test-data`. Режим `--example` является явным разрешением демонстрационных данных. Это не преобразует их в реальные данные.

Ошибка одного модуля не отменяет успешные результаты других. Код завершения 0 означает отсутствие ошибок модулей, 2 означает частичный или неуспешный запуск. Точное описание ошибок находится в `run_info.json` и HTML.

Файлы модулей с ошибкой могут отсутствовать. Сохранённые параметры плюс `effective_forward_parameters.json` учитывают и файл настроек, и узловые переопределения. Источники подставленных блоков, SHA-256 исходных JSON и замены архива записаны в `run_info.json`.

XLSX содержит один лист с 39 узлами сегодняшней кривой, датами экспирации, ценами, источниками и числом переносов. Цены числовые, отображаются до двух знаков. У Excel ограниченная числовая точность; для точного обмена используй JSON. Отсутствующая цена остаётся пустой, не превращается в ноль. Интерполированная кривая отдельно сохраняется по календарным дням, без экстраполяции и соединения пропусков.

NPZ содержит FHS и исторические сценарные кривые: пары матриц N×39. Это не pickle: для чтения `numpy.load(path, allow_pickle=False)`. Сценарные матрицы и JSON результатов не меняются при редактировании портфеля на странице.

## Мини-фронт

Модуль называется `test/`, проверки Python остаются в `tests/`. В HTML есть график сегодняшней кривой с линейной осью цен и шагом 100 руб./т, сохранённые NPV/ГО, форма NPV сделки и редактор массива сделок портфеля. Интерполяция кривой остаётся log-linear; шкала графика не меняет финансовую математику. Над редактором приведены поля и пример JSON-массива из двух сделок. Пример не подставляется в исходный портфель. Даты, сторона, цена и объём сделки изменяемы; параметры методики и рыночные кривые зафиксированы запуском.

Для каждого запроса ГО используется один подготовленный набор сценариев без повторной калибровки GARCH. Ограничения по фиксации после горизонта риска сохраняются. Введённые через страницу сделки и результаты пересчётов на диск не записываются. Исходный портфель запуска сохраняется вместе с остальными входами для воспроизводимости.

Сервер слушает только 127.0.0.1, разрешает доступ только к HTML и XLSX. Архив и входные позиции по HTTP не раздаются. Пересчёты требуют токен сессии и корректный Origin. Публичное размещение этого тестового сервера не предусмотрено.

## Перенос и Git

Пути вычисляются относительно проекта, не домашней папки автора. Для Windows не нужна база часовых поясов: дата Москвы вычисляется как UTC+03:00. На macOS/Linux окружение запускается через `.venv/bin/python`; отдельная проверка на этих ОС пока не проводилась.

В Git не включаются `.venv/`, `output/`, пользовательские файлы `input/`, `.env` и служебные папки. `default_input/` предназначена только для распространяемых демонстрационных данных. Проект на GitHub пока не опубликован.

```powershell
.venv/Scripts/python.exe -m unittest discover -s tests -q
.venv/Scripts/python.exe -m pip check
```
